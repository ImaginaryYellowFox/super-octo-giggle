# Проект 3. Incident Radar

CLI-утилита для анализа NGINX-логов. Читает логи (файлы, glob-маски или URL),
разбирает строки, фильтрует по датам и строит отчёт со статистикой.

Одна строка лога выглядит так:

```text
93.180.71.3 - - [17/May/2015:08:05:32 +0000] "GET /downloads/product_1 HTTP/1.1" 304 0 "-" "Debian APT-HTTP/1.3"
```

Из неё утилита достаёт IP, дату, метод, ресурс, код ответа и размер ответа.
А из миллиона таких строк собирает картину: сколько запросов, какие endpoint'ы
популярны, сколько ошибок, какие ответы самые тяжёлые.

Здесь впервые появляются «взрослые» требования: файл может быть гигантским
(читаем потоково), строки бывают битыми (пропускаем, а не падаем), а утилиту
будут запускать скрипты (значит, нужны честные коды возврата).

## Как проверить загрузку логов по HTTP

Для ручной проверки можно раздать готовые сэмплы локальным HTTP-сервером.
Из корня проекта запусти (нужен Python 3):

```bash
python -m http.server 8000 --bind 127.0.0.1 --directory samples/logs
```

Оставь этот терминал открытым. По адресу <http://127.0.0.1:8000/> будет список
файлов. В `--path` передавай URL конкретного лога, а не страницы со списком:

```bash
./gradlew run --args='--path http://127.0.0.1:8000/access-2025-03-01.log'
```

Эта проверка имеет смысл после реализации чтения по URL: стартовый шаблон
ещё не обрабатывает аргументы. Остановить HTTP-сервер можно через `Ctrl+C`.

В автоматических тестах сервер должен запускаться и останавливаться самим
тестом, например через Java `HttpServer`. Используй loopback-адрес и порт `0`
(ОС выберет свободный порт), настрой ответы `200` с тестовым логом и `404`,
а в приложение передавай URL с фактическим портом сервера. Останавливай сервер
в `finally` или `@AfterEach`, даже если проверка упала. Тогда тесты смогут
работать в GitLab CI без вручную запущенного сервера и внешних сайтов.

## Запуск

```bash
./gradlew run --args="--path <файл|маска|URL> [опции]"
```

Поддерживаемые расширения логов: `.log`, `.txt`.

### Примеры запуска

```bash
# Один файл
./gradlew run --args="--path samples/logs/access-2025-03-01.log"

# Все файлы по маске
./gradlew run --args="--path 'samples/logs/access-*.log'"

# Рекурсивная маска: .log-файлы во всех вложенных папках
./gradlew run --args="--path 'samples/**/*.log'"

# Несколько источников сразу, в том числе разных типов
./gradlew run --args="--path samples/logs/reference-codes.log 'samples/logs/access-*.log'"

# Только --from: второй день
.\gradlew.bat run --args="--path 'samples/logs/access-*.log' --from 2025-03-02"

# Только --to: первый день
.\gradlew.bat run --args="--path 'samples/logs/access-*.log' --to 2025-03-01"

# Файл с битыми строками: 7 записей, 6 предупреждений в stderr
./gradlew run --args="--path samples/logs/malformed.log"
```

### Параметры

| Параметр | Описание |
|---|---|
| `--path`, `-p` | Файл, glob-маска или URL. Можно указать **несколько** значений |
| `--output-format`, `-f` | `json` или `markdown`, регистр не важен. По умолчанию `markdown` |
| `--output-path`, `-o` | Путь для файла отчёта. Расширение должно соответствовать формату: `.json` или `.md` |
| `--from` | Начало периода, формат `yyyy-MM-dd` |
| `--to` | Конец периода, формат `yyyy-MM-dd` |
| `--help`, `-h` | Справка |
| `--version`, `-V` | Версия |

обязательным параметром является `--path`

### Описание метода расчёта p95

- **p95 - метод nearest rank**: значение с номером `ceil(0.95 * n)` в выборке,
  отсортированной по возрастанию (нумерация с 1).
    - результат является реальным размером ответа из данных;
    - формула однозначна, у интерполяции несколько распространённых вариантов;
    - на эталоне `100..500` даёт 500, как  и по заданию (линейная интерполяция в варианте
      numpy дала бы 480); на сэмплах даёт 5450 (интерполяция - 5450.20).
      Ранг считается в целых числах (`Math.ceilDiv(95 * n, 100)`), без `double`:
      `0.95` неточно представляется в двоичном виде, и `ceil` мог бы дать лишнюю единицу.


## Устройство проекта

Путь одной строки:

```text
источник ──строки──> LogParser ──LogRecord──> DateRange ──> StatisticsCollector ──> Statistics
                         │                        │
                         └─ битая: WARN, пропуск  └─ вне периода: не учитывается
```

```text
src/main/java/academy/incidentradar/
├── Main.java                       точка входа в программу
├── cli/
│   ├── IncidentRadarCommand.java   опции, валидация аргументов, запуск радара, вывод результата
│   └── OutputFormat.java           форматы отчёта и их расширения
├── app/
│   ├── IncidentRadar.java          запуск анализа: источники -> парсер -> фильтр -> статистика
│   └── RadarResult.java            итог: источники, статистика, счётчики пропущенных строк
├── source/
│   ├── LogSource.java              интерфейс источника: «отдай строки по одной»
│   ├── LocalFileSource.java        чтение локального файла через Files.lines()
│   ├── UrlLogSource.java           чтение по HTTP через HttpClient + BodyHandlers.ofLines()
│   ├── LogSourceException.java     источник недоступен по вине пользователя (код 2)
│   └── resolver/
│       ├── SourceResolver.java     интерфейс стратегии: supports(path) + resolve(path)
│       ├── UrlSourceResolver.java  http:// и https://
│       ├── GlobSourceResolver.java маски с * ? [ {
│       ├── FileSourceResolver.java обычный путь
│       ├── LogSourceResolver.java  выбирает первый подходящий резолвер
│       └── SourceChecks.java       общие проверки: расширение, корректный путь
├── model/
│   └── LogRecord.java              одна разобранная строка лога
├── parser/
│   └── LogParser.java              строка -> Optional<LogRecord>
├── filter/
│   └── DateRange.java              период по датам, Predicate<LogRecord>
└── stats/
    ├── StatisticsCollector.java    накапливает статистику по записям, Consumer<LogRecord>
    ├── SizeHistogram.java          распределение размеров: average, max, перцентиль
    ├── Statistics.java             итоговая статистика
    ├── ResponseSizeStatistics.java average / max / p95
    └── ResourceCount.java          ресурс и число запросов к нему
```
